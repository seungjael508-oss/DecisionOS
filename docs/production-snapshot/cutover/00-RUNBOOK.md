## 롤백 절차(장애 시)

1. **코드 먼저**: `dpl_4fWYuqZUXL8nDQmuS1d91mi6jZno` 재승격. 신규 코드가 남은 채 R3(방문대상 테이블 삭제)을 실행하면 오늘 관리대상 화면이 깨진다.
2. 기존 코드 + 신규 DB 상태의 알려진 영향(즉시 롤백 사유인지 판단):
   - 오늘 관리대상이 C·D 한정, 새 사유가 코드명으로 표시, '다음 접촉 도래' 필터 0건 → 업무 공지로 감내 가능
   - **상담사가 D를 고르면 DB가 거부하는데 기존 화면은 "저장 여부 확인 불가"로 표시** → 현장 혼선·누락 위험. 감내 불가하면 R1·R2까지 롤백
   - 자동 D 전환은 DB에서 계속 동작
3. DB 롤백이 필요하면: **05a 실행 → E1 백업 → 05c PASS → 06 결과 보관** 후 R1 → R2 → R3 → R4(필요한 만큼만).
   - 06에 자동 D가 1건이라도 있으면(contract_status_history의 'legacy_grade' 이력) R3은 전체 중단된다(변경 없음). 이때는 R1·R2까지만 롤백하고, R3·R4는 이력 처리 방법을 별도 승인으로 정한 뒤 진행한다.
4. 롤백 후 03을 다시 실행해 mig_* 상태가 기대와 같은지 확인.
5. 자동 변경된 D등급·등급 이력·상담은 되돌리지 않는다. 재조정은 상담사 수동 판단(06b로 대상 확인).
6. 나중에 재적용할 때는 A1~A4 후 E2로 방문대상을 복구하고 05c로 확인.
